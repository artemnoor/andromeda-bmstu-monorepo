# Проходные баллы из официальных карточек и приказов — 20–21.10.2026

## Правило источников

Числовые проходные баллы каталога и сравнения сначала берутся из `additional.oldPoints.2026.budget` и `.paid` точной официальной карточки направления на `api.www.bmstu.ru`. Если карточка не содержит числа, для программы с подтверждённым московским кампусом используется минимум суммы баллов в основном приказе по общему конкурсу, когда источник подтверждён официальной ссылкой на нужный PDF или проверенным SHA-256. Бюджет сверяется с `first_msk_main.pdf`, платное обучение — с `first_msk_paid.pdf`; приоритетные приказы и отдельные квоты не подменяют общий конкурс. Московские приказы не используются для других и неподтверждённых кампусов. Если числа нет в обоих источниках, показывается «Не опубликован». Отметка «БВИ вне квот» подтверждается отдельно приоритетным приказом, а не прочерком в карточке. Из приказов также берётся количество зачисленных: бюджет, платное и части бюджета по квотам.

Карточка публикует агрегат направления, поэтому одно значение может повторяться у нескольких его профилей. Интерфейс явно указывает уровень направления и открывает обычную официальную страницу `https://bmstu.ru/bachelor/majors/<slug>`. Технический API URL сохраняется в происхождении данных и проверках идентичности. Квотных проходных в карточках нет: таблица проходных содержит бюджет и платное; квоты остаются в таблице зачисления. Бюджет не назван «общим конкурсом» без соответствующего обозначения в источнике.

Все 53 публичные страницы проверены по HTTP и встроенным данным страницы: код направления, slug и значения `oldPoints.2026` совпадают с исходной карточкой. [Результат проверки](data/official-source-pages-20261020.json). Преобразование URL применяется только при отображении ссылок «Источник» в карточках каталога и общих таблицах каталога/сравнения. PDF приказов и учебных планов сохраняют точные адреса и страницы.

Проверки ссылок: 40 ближайших тестов компонентов и модели, TypeScript strict, ESLint, production build и Chromium-сравнение проходят. Браузерная сверка проверяет ссылки в каждой из 152 карточек: технические `/majors/...` заменены публичной страницей; `/file/<id>/download` сохранены как оригинальные документы. Исходные API URL и хеши продолжают проверяться независимо от ссылок интерфейса. Обновление опубликовано 21.10.2026; резервная статика — `/home/yc-user/deploy/andromeda-preview.public-links-20261021-backup`.

Прочерк, отсутствующее поле и null не превращаются в 0 или БВИ. Прошлогодние значения не подставляются. Нулевой числовой результат сохраняется, только если опубликован именно числом. Конфликтующие официальные записи не разрешаются выбором самого маленького балла. Ошибка запроса отличается от отсутствия опубликованного результата.

Версия о том, что ИУ7-11БВ относится к ГУИМЦ, не подтверждена и не используется как правило парсинга.

Проверены все **53 карточки / 152 программы** текущего каталога. Во всех карточках есть раздел 2026 года. Это не означает, что каждое его поле заполнено числом.

У 24.05.01 оба поля содержат прочерки; это затрагивает 13 профилей. Данные не выдумываются ради полного заполнения таблицы. Остальные направления имеют хотя бы одно числовое значение.

Для **09.03.04 «Программная инженерия»**: в официальной карточке бюджет — прочерк, платное — **259**. После проверки полного списка московских приказов интерфейс поясняет бюджет как **«БВИ вне квот»**: в приоритетном приказе §501–525 содержатся 25 таких зачисленных, в основном приказе направления нет. Остальные 59 бюджетников относятся к квотам (9 особая, 13 отдельная, 37 целевая), среди них есть поступившие с баллами. Поэтому утверждение «все бюджетники — БВИ» неверно. Платный минимум **193** из приказа не заменяет число **259** из карточки; целевые **174** относятся к отдельной квоте и не являются общим конкурсом. Итоги остаются 84 на бюджет и 94 на платное.

## Проверка смысла прочерков

Повторно получены официальный `lists/orders.json`, оба московских бюджетных приказа и десять карточек без числового бюджетного балла. Независимый подсчёт параграфов по полным разделам PDF, без сохранения записей абитуриентов: [аудит](data/bvi-orders-20261020.json).

| --- | ---: | ---: | --- |
| 01.03.02 | 6 | 0 | БВИ вне квот |
| 09.03.04 | 25 | 0 | БВИ вне квот |
| 14.05.01 | 10 | 0 | БВИ вне квот |
| 10.05.03 | 7 | 8 | 296 из основного приказа |
| 15.03.06 | 80 | 19 | 296 из основного приказа |
| 24.05.01 | 37 | 72 | 277 из основного приказа |

Для 38.03.01, 38.03.02, 45.03.02 и 45.03.03 бюджетных зачислений в этих приказах нет; прочерк также не превращается в БВИ.

Отметка использует положительное свидетельство API: текущий год, подтверждённый московский кампус, отдельный маршрут `bvi`, положительное число зачисленных и проверенный SHA-256 московского приоритетного приказа. Наличие любой записи общего/неизвестного конкурса блокирует отметку, даже если её балл не разобран или запись относится к кафедре. Квотное БВИ не подходит. Неизвестный кампус, другой год, неизвестный источник, конфликт количества, отсутствие карточки или конфликт её версий сохраняют неопределённость. Число из карточки имеет приоритет; если его нет, применяется проверенный основной приказ по общему конкурсу. Рядом показываются отдельно карточка и точная страница приказа; интерфейс не утверждает, что весь бюджет направления состоит из БВИ.

Проверки дополнения: регрессия «карточка без числа + подтверждённые 25 БВИ → Не опубликован» воспроизведена до исправления. После исправления проходят 160 Vitest-тестов, проверка типов, ESLint и production build; семь сценариев Chromium с настоящим API проходят локально. Полная браузерная сверка 152 программ проходит [локально](data/bvi-scores-ui-20261020-local.json) и [на опубликованной VM](data/bvi-scores-ui-20261020-live.json). Отметку получили пять профилей трёх направлений; прочие пропуски не заменялись. На VM отдельно проверено сравнение, включая мобильную ширину 390 px.

Для этих проверенных хешей интерфейс восстанавливает прямую ссылку на соответствующий PDF. Будущие API-записи принимаются также при точном URL соответствующего официального PDF. Резерв включён только для программ с подтверждённым московским кампусом, чтобы московский приказ не стал результатом для Калуги или неуточнённой площадки.

Квотные баллы и записи с неизвестным конкурсом в резервный проходной не попадают.

## Реализация и достоверность

- Парсер и построитель нового пакета: `services/ingestion/src/andromeda_parser/official_card_scores.py`. Проверяются точные URL, SHA-256, год, direction code, принадлежность каждого профиля своей карточке и допустимая область источника. Числа ограничены целыми 0–400; bool и неожиданный текст отклоняются.
- Добавлены 106 фактов существующего набора `historical_admission_statistics` с отдельным видом `official_program_card_passing_score` и 53 версии источников, привязанные к URL и содержимому. Новая схема БД, endpoint или прямые внешние запросы браузера не понадобились. Существующие API-контракты совместимы.
- React использует существующий единый API adapter и отдельную коллекцию официальных проходных. Приказные `campaignResults` сохранены для зачисления. Каталог и сравнение используют одну таблицу и один селектор.
- У 9 программ кампус ранее не подтверждён. Их статус не менялся. При точном совпадении карточки показывается только агрегат её направления; это не утверждение о кампусе/конкурсе отдельного профиля. Явные филиальные области отвергаются.
- Старый опубликованный пакет не изменялся. Новый выпуск построен из точного пакета активного релиза `a6fd1db9…`, с проверкой SHA и ожидаемого UUID перед публикацией.

Повторяемая подготовка нового пакета из проверенной capture-записи:

```powershell
.venv/Scripts/python.exe -m andromeda_parser.official_card_scores `
  --input <точный-базовый-пакет> --capture <capture.json> `
  --output <новый-каталог> --year 2026
```

Команда не публикует результат, не меняет входной пакет и отказывается перезаписывать существующие ключи. Повторное изменение уже добавленных фактов требует нового проверенного кандидата, а не редактирования активного release.
