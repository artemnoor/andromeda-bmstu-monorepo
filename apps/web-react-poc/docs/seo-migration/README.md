Не перенаправлять, не закрывать от индексации и не удалять старые проекты в рамках SEO нового сайта.

Новый сайт https://andromedabmstu.ru продвигается как самостоятельный ресурс для выбора и сравнения образовательных программ МГТУ им. Баумана. Он отдаёт готовый HTML, метаданные, sitemap и favicon. ## Готовые файлы

- `proc-sima.vercel.json` — правила HTTP 301 для главной и профтеста. Их нужно **объединить с существующим vercel.json старого проекта**, сохранив остальные настройки, затем опубликовать проект. Не устанавливать этот файл в проект нового сайта. Неизученные страницы не отправляются массово на главную: сначала нужна карта соответствия.
- `z-ai-index.html` — замена старой `/andromeda/index.html` для случая, когда хостинг не даёт настроить HTTP 301. Сначала сохранить оригинал. Содержит canonical, немедленное HTML-перенаправление и обычную ссылку на новый сайт. Если Z.ai поддерживает серверные редиректы, выбрать HTTP 301 вместо HTML-перенаправления. Другие файлы старого проекта не меняются.

Для переноса `/andromeda/catalog.html` сначала проверить соответствие содержания новому `/programs`; страница `timeline.html` не имеет подтверждённого аналога. Перенос старых результатов профтеста между несовместимыми версиями не реализован: пользователь попадает в новый тест.

## Почему не опубликовано автоматически

DNS `proc-sima.ru` обслуживают `ns1.reg.ru` / `ns2.reg.ru`, сайт размещён на Vercel. Подключённая команда Vercel `team_wT8C3MEYaLo5dwSdQqBL7XS9` вернула пустой список проектов; обращение к домену вернуло 403. CLI без авторизации. DNS-зоны proc-sima.ru в доступном профиле Yandex Cloud нет. Доступ к редактору/хостингу Z.ai также не подключён. Это отсутствие нужного доступа, а не требование повторно согласовать уже разрешённую работу.

Нужен доступ к проекту старого сайта в Vercel и к исходному проекту Z.ai либо применение этих подготовленных файлов владельцем.

## После публикации

1. Проверить старые адреса: HTTP 301 с Location на соответствующий новый адрес; для HTML-варианта Z.ai проверить refresh и canonical в исходном HTML.
2. Проверить целевые страницы: HTTP 200, правильные canonical, отсутствие циклов перенаправления.
3. В Яндекс Вебмастере подтвердить оба управляемых домена и оформить «Индексирование → Переезд сайта». Для подкаталога чужого домена Z.ai возможности зависят от доступного типа подтверждения.
4. В Google Search Console проверить URL главной и `/compare` нового сайта, отправить запрос на индексирование и sitemap. Старые страницы с редиректами должны оставаться доступными для обхода.

Переезд помогает поисковой системе связать адреса, но не гарантирует сохранение или рост позиции. Верхние места зависят от обработки переезда и оценки страниц поисковиком.
